Daily Aqua Briefing API

Use the API to read your briefing and to add or update projects, quick tasks, and daily tasks from a script, a Power Automate flow, or Claude. The API changes only your own briefing. It can read anyone's briefing, because briefings are already viewable by link.

It does not delete items. Delete them on the Dashboard.

1. Get an API key

  1. Open the Dashboard and go to Settings → API Access.
  2. Type a name for the key (for example Power Automate) and click Create Key.
  3. Copy the key. It starts with dab_ and is shown only once.
Treat a key like a password: don't email it, paste it into chat, or commit it to a repo. Anyone with the key can change your briefing. If a key leaks, click Revoke next to it in Settings, and anything using it stops working. Each person can have up to 5 keys.

2. Send requests

Base URL:

https://us-central1-dailybriefing-fe7df.cloudfunctions.net/briefingApi

Send the key in a header on every request:

Authorization: Bearer dab_your_key_here

If a tool can't set an Authorization header, send X-API-Key: dab_your_key_here instead.

Send and receive JSON (Content-Type: application/json). Errors come back with an HTTP error status and {"error": "what went wrong"}.

Endpoints

RequestWhat it does
GET /briefingSummary: owner, department, last update, item counts by section and status.
GET /items/{section}List items in a section (id, name, status, priority, owner, dates, milestone progress). Query options: status=Planning, q=words to find, includeCompleted=false, full=1 for every field.
GET /items/{section}/{id}One item with notes, goal, milestones, attachments, comments, and recent daily checks.
POST /items/{section}Add an item to the top of the section. name is required.
PATCH /items/{section}/{id}Change an item. Only the fields you send change.
POST /mcpMCP connector endpoint for Claude (see section 4).

Add ?report=mhevey (any Aqua Network ID) to a GET to read someone else's briefing. Without it you get your own.

Sections

{section}Dashboard tab
projectsActive Projects
quickTasksQuick Tasks
dailyTasksDaily Tasks (no status, priority, or Assigned To)

Item fields

FieldValue
nameText, up to 200 characters.
statusOne of: Planning, Requirement Gathering, Training, In Progress, Development, Testing, Review, Delayed, Future, On-Hold, Completed, Follow-Up, Maintenance, On Track. New items default to On Track.
priorityHigh, Medium, or Low. Defaults to High.
assignedToOwner's name. Defaults to N/A.
goal, tester, collaboratorsText.
startDate, endDateYYYY-MM-DD, or "" to clear.
notesPlain text; each line becomes a paragraph. Replaces the existing notes, including any formatting.
appendNotesPlain text added to the end of the notes (PATCH only). Use this for log-style updates.
milestonesThe full milestone list (see below). It replaces the existing list, so GET the item first and send back every milestone you want to keep.

Text fields can't contain < or >; the API removes them. Last Updated is set for you on every change.

Milestone fields

FieldValue
nameRequired. Milestones without a name are dropped.
baseDateBase complete date, YYYY-MM-DD.
estActDateEstimated or actual complete date, YYYY-MM-DD.
donetrue when complete.
inProgress, onHold, roadblockAt most one can be true.
holdReason, blockReasonWhy it's on hold or blocked. The roadblock reason shows on the Status Report.

3. Examples

Python

import os, requests

API = "https://us-central1-dailybriefing-fe7df.cloudfunctions.net/briefingApi"
HEADERS = {"Authorization": "Bearer " + os.environ["DAB_API_KEY"]}

# Open projects that mention "dashboard"
r = requests.get(API + "/items/projects", headers=HEADERS,
                 params={"q": "dashboard", "includeCompleted": "false"})
r.raise_for_status()
for item in r.json()["items"]:
    print(item["id"], item["status"], item["name"])

# Add a quick task
r = requests.post(API + "/items/quickTasks", headers=HEADERS, json={
    "name": "Renew SSL certificate",
    "priority": "Medium",
    "endDate": "2026-10-31",
    "notes": "Requested by the web team.",
})
new_id = r.json()["item"]["id"]

# Mark it in progress and add a note
requests.patch(API + "/items/quickTasks/" + new_id, headers=HEADERS, json={
    "status": "In Progress",
    "appendNotes": "Ordered the certificate.",
}).raise_for_status()

Keep the key in an environment variable or a secrets store, not in the script.

curl

curl -H "Authorization: Bearer $DAB_API_KEY" \
  "https://us-central1-dailybriefing-fe7df.cloudfunctions.net/briefingApi/briefing"

curl -X PATCH -H "Authorization: Bearer $DAB_API_KEY" -H "Content-Type: application/json" \
  -d '{"status": "Review"}' \
  "https://us-central1-dailybriefing-fe7df.cloudfunctions.net/briefingApi/items/projects/item_123"

Power Automate

Use the HTTP action:

  • Method: GET, POST, or PATCH.
  • URI: the base URL plus the path, for example .../briefingApi/items/quickTasks.
  • Headers: Authorization = Bearer dab_... and Content-Type = application/json.
  • Body: the JSON fields, for example {"name": "Follow up with vendor", "priority": "High"}.

Store the key in a secure input or an environment variable so it doesn't show in run history.

4. Connect Claude (MCP connector)

The /mcp endpoint is an MCP server, so Claude can work with your briefing directly ("add a project for the OTD metric changes", "what's on hold?", "mark the Publish milestone done"). It provides five tools: get_briefing, list_items, get_item, create_item, and update_item.

Claude Code

claude mcp add --transport http daily-briefing ^
  https://us-central1-dailybriefing-fe7df.cloudfunctions.net/briefingApi/mcp ^
  --header "Authorization: Bearer dab_your_key_here"

That's for the Windows Command Prompt. On macOS, Linux, or Git Bash, use \ instead of ^ at the end of each line. Run /mcp in Claude Code to confirm it shows as connected.

Claude Desktop

Add this to claude_desktop_config.json (Settings → Developer → Edit Config); it needs Node.js installed:

{
  "mcpServers": {
    "daily-briefing": {
      "command": "npx",
      "args": ["-y", "mcp-remote",
        "https://us-central1-dailybriefing-fe7df.cloudfunctions.net/briefingApi/mcp",
        "--header", "X-API-Key:dab_your_key_here"]
    }
  }
}

Claude on the web (claude.ai) can't connect with a key yet; it needs a sign-in flow that this API doesn't have.

Good to know

  • New items go to the top of their tab, like items added on the Dashboard.
  • The Dashboard updates live, so changes made through the API appear right away if it's open.
  • A change made through the API is stored the same way as a Dashboard edit, so it shows on the briefing and the Status Report.
  • Every change is logged with the key's first few characters, so a misbehaving key can be traced and revoked.
