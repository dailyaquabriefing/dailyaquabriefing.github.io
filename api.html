Daily Aqua Briefing API

The API lets a script, a Power Automate flow, or Claude read your briefing and add or update your projects, quick tasks, and daily tasks.

  • A key changes only your own briefing. It can read anyone's briefing, because briefings are already viewable by link.
  • The API does not delete items. Delete them on the Dashboard.
On this page
  1. Create an API key (anyone with a Dashboard account)
  2. Connect to the API (developers): store the key, test, make calls
  3. Code examples: Python, Node.js, C#, curl, Power Automate

PART 1Create an API key

Do this once for each app or flow that will use the API. Then give the key to the developer, or put it in your own tool.

Before you start

  • You need a Dashboard sign-in. If you don't have one, ask IT.
  • You must have signed in to the Dashboard at least once and linked your Aqua Network ID (for example jdoe). The Dashboard asks for it the first time you sign in.

Steps

  1. Open the Dashboard and sign in.
  2. Click the Settings tab.
  3. Scroll down to API Access.
  4. In Key name, type what the key is for, for example Power Automate - weekly status or Claude Code. The name helps you tell your keys apart later.
  5. Click Create Key.
  6. A yellow box shows the key. It starts with dab_. Click Copy.
  7. Paste the key where it will be used (see Store the key). The key is shown only once. If you lose it, revoke it and create a new one.
Treat a key like a password. Anyone who has it can change your briefing.
  • Don't email it, put it in a Teams chat, paste it into a Claude chat, or commit it to a repo.
  • Use a separate key for each app, so you can turn one off without breaking the others.
  • You can have up to 5 keys.

Turn off a key

In Settings → API Access, click Revoke next to the key. Anything using it stops working right away. The list also shows when each key was last used, which tells you which keys are still in use.

PART 2Connect to the API (developers)

Step 1. Store the key

Keep the key out of your code. Put it in an environment variable named DAB_API_KEY, or in your app's secrets store (Azure Key Vault, Power Automate secure inputs, and so on).

On Windows, in Command Prompt:

setx DAB_API_KEY "dab_paste_your_key_here"
Now close that Command Prompt and open a new one. setx saves the key for windows you open later, not the one you ran it in. If you skip this, the test below sends the text %DAB_API_KEY% instead of your key and fails.

Step 2. Test the connection

In the new Command Prompt, run:

curl -H "Authorization: Bearer %DAB_API_KEY%" https://us-central1-dailybriefing-fe7df.cloudfunctions.net/briefingApi/briefing
It works if you get JSON back with your reportId (your Aqua Network ID) and item counts, like this: 
{
  "reportId": "jdoe",
  "displayName": "Jane Doe",
  "department": "Information Technology",
  "lastUpdated": "2026-10-05T15:39:54.920Z",
  "briefingUrl": "https://dailyaquabriefing.github.io/index.html?report=jdoe",
  "sections": {
    "projects":   { "count": 4, "byStatus": { "On Track": 3, "Planning": 1 } },
    "quickTasks": { "count": 2, "byStatus": { "In Progress": 2 } },
    "dailyTasks": { "count": 0, "byStatus": {} }
  }
}

If you get {"error": ...} instead, see Errors.

Step 3. Make calls

Every request goes to the base URL, sends the key in a header, and uses JSON:

ItemValue
Base URLhttps://us-central1-dailybriefing-fe7df.cloudfunctions.net/briefingApi
Auth headerAuthorization: Bearer dab_...
If your tool can't set an Authorization header, send X-API-Key: dab_... instead.
BodyJSON, with Content-Type: application/json

The usual pattern for changing an item:

  1. Find it: GET /items/projects?q=dashboard returns matching items with their id.
  2. Change it: PATCH /items/projects/{id} with only the fields that change, for example {"status": "Review"}.

Item ids never change, so you can save an id and reuse it. See the Reference for every endpoint and field.

Code examples

Python

Needs the requests package (pip install requests).

import os
import requests

API = "https://us-central1-dailybriefing-fe7df.cloudfunctions.net/briefingApi"
HEADERS = {"Authorization": "Bearer " + os.environ["DAB_API_KEY"]}

def call(method, path, **kwargs):
    r = requests.request(method, API + path, headers=HEADERS, timeout=30, **kwargs)
    if not r.ok:
        raise RuntimeError(f"{r.status_code}: {r.json().get('error')}")
    return r.json()

# Open projects that mention "dashboard"
found = call("GET", "/items/projects", params={"q": "dashboard", "includeCompleted": "false"})
for item in found["items"]:
    print(item["id"], item["status"], item["name"])

# Add a quick task
created = call("POST", "/items/quickTasks", json={
    "name": "Renew SSL certificate",
    "priority": "Medium",
    "endDate": "2026-10-31",
    "notes": "Requested by the web team.",
})
task_id = created["item"]["id"]

# Mark it in progress and add a line to its notes
call("PATCH", f"/items/quickTasks/{task_id}", json={
    "status": "In Progress",
    "appendNotes": "Ordered the certificate.",
})

Node.js (18 or later)

const API = "https://us-central1-dailybriefing-fe7df.cloudfunctions.net/briefingApi";

async function call(method, path, body) {
  const res = await fetch(API + path, {
    method,
    headers: {
      Authorization: `Bearer ${process.env.DAB_API_KEY}`,
      "Content-Type": "application/json",
    },
    body: body ? JSON.stringify(body) : undefined,
  });
  const data = await res.json();
  if (!res.ok) throw new Error(`${res.status}: ${data.error}`);
  return data;
}

const onHold = await call("GET", "/items/projects?status=On-Hold");
console.log(onHold.items.map((i) => `${i.id}  ${i.name}`).join("\n"));

await call("POST", "/items/projects", {
  name: "OTD metric changes",
  status: "Planning",
  assignedTo: "Mike Hevey",
  milestones: [{ name: "Requirements", baseDate: "2026-10-15" }],
});

Run it as an ES module (a .mjs file) so top-level await works. Don't put a key in browser JavaScript on a shared web page: anyone who opens the page could read it.

C# (.NET 7 or later)

using System.Net.Http.Headers;
using System.Net.Http.Json;

var http = new HttpClient {
    BaseAddress = new Uri("https://us-central1-dailybriefing-fe7df.cloudfunctions.net/briefingApi/")
};
http.DefaultRequestHeaders.Authorization = new AuthenticationHeaderValue(
    "Bearer", Environment.GetEnvironmentVariable("DAB_API_KEY"));

// Read the summary (paths have no leading slash because of BaseAddress)
string summary = await http.GetStringAsync("briefing");

// Add a project
var create = await http.PostAsJsonAsync("items/projects", new {
    name = "Update Executive Dashboard",
    priority = "High",
    endDate = "2026-10-31"
});
create.EnsureSuccessStatusCode();

// Change its status (replace item_123 with the id from the create response)
var update = await http.PatchAsJsonAsync("items/projects/item_123", new { status = "Review" });
update.EnsureSuccessStatusCode();

curl (Command Prompt)

REM List quick tasks
curl -H "Authorization: Bearer %DAB_API_KEY%" "https://us-central1-dailybriefing-fe7df.cloudfunctions.net/briefingApi/items/quickTasks"

REM Add a quick task (quotes inside the JSON are escaped with \ in Command Prompt)
curl -X POST -H "Authorization: Bearer %DAB_API_KEY%" -H "Content-Type: application/json" ^
  -d "{\"name\": \"Call vendor about quote\", \"priority\": \"High\"}" ^
  "https://us-central1-dailybriefing-fe7df.cloudfunctions.net/briefingApi/items/quickTasks"

In Git Bash, macOS, or Linux, use $DAB_API_KEY instead of %DAB_API_KEY%, use \ instead of ^ at line ends, and wrap the JSON in single quotes.

Power Automate

  1. Add an HTTP action. It's a premium connector.
  2. Method: GET, POST, or PATCH.
  3. URI: the base URL plus the path, for example https://us-central1-dailybriefing-fe7df.cloudfunctions.net/briefingApi/items/quickTasks.
  4. Headers: Authorization = Bearer dab_... and Content-Type = application/json.
  5. Body (POST and PATCH): the JSON fields, for example {"name": "Follow up with vendor", "priority": "High"}.
  6. In the action's Settings, turn on Secure inputs so the key doesn't show in run history.
  7. To use the response, add a Parse JSON action on the HTTP action's Body.

Connect Claude

The API includes an MCP connector, so Claude can work with a briefing directly. For example, you can ask it to "add a project for the OTD metric changes", "what's on hold?", or "mark the Publish milestone done". It provides five tools: get_briefing, list_items, get_item, create_item, and update_item.

Fill in your key first. Paste your key in this box, and the steps below show it in place of dab_paste_your_key_here, ready to copy. The key stays in this browser tab: the page doesn't send it anywhere or save it.
That doesn't look like a key. Keys start with dab_.

Claude Code

  1. Create a key named Claude Code (Part 1) and paste it in the box above.
  2. In Command Prompt, run this. It's one command on three lines: 
    claude mcp add --transport http --scope user daily-briefing ^
  https://us-central1-dailybriefing-fe7df.cloudfunctions.net/briefingApi/mcp ^
  --header "Authorization: Bearer dab_paste_your_key_here"
    --scope user makes it available in every folder, in the terminal and in VS Code. Without it, it works only in the folder where you ran the command. In Git Bash, macOS, or Linux, use \ instead of ^.
  3. Start Claude Code (or reload VS Code) and type /mcp. daily-briefing should show as connected.
  4. Try it: "Using daily-briefing, list my open projects."

Claude Desktop

Claude Desktop runs the connector with Node.js. To check that Node.js is installed, open Command Prompt and run node -v. A version number (for example v22.11.0) means it's installed. If you get "not recognized", install it from nodejs.org or ask IT.

  1. Create a key named Claude Desktop (Part 1) and paste it in the box above.
  2. In Claude Desktop, open Settings → Developer and click Edit Config. This opens the settings file, or a folder with claude_desktop_config.json in it. Open that file in Notepad: right-click it and choose Open with → Notepad.
  3. The file has many settings. You change only one line. Near the top, find: 
      "mcpServers": {},
  4. Select that one line and replace it with this text. Leave everything else in the file as it is. 
      "mcpServers": {
    "daily-briefing": {
      "command": "npx",
      "args": [
        "-y",
        "mcp-remote",
        "https://us-central1-dailybriefing-fe7df.cloudfunctions.net/briefingApi/mcp",
        "--header",
        "X-API-Key:dab_paste_your_key_here"
      ]
    }
  },
  5. Save the file (Ctrl+S) and close Notepad.
  6. Quit Claude Desktop completely. Closing the window isn't enough: right-click the Claude icon in the system tray (bottom-right of the taskbar) and choose Quit. Then open Claude Desktop again.
  7. Check it: in Settings → Developer, daily-briefing should show as running. Then, in a new chat, ask: "Using daily-briefing, list my open projects."

If your file looks different

Your file hasDo this
"mcpServers": {} with no comma after itIt's the last setting in the file. Paste the text above, then delete the comma after its final }.
No "mcpServers" linePaste the text on a new line right after the first { at the top of the file.
"mcpServers" with other servers in itCopy the text above without its first line ("mcpServers": {) and last line (},). Paste it on a new line right after "mcpServers": {, and add a comma after the pasted block's last } so it's separated from the next server.

Troubleshooting Claude Desktop

  • Claude Desktop shows an error about the config file when it opens: a comma or brace is out of place. Open the file again and compare it with the text above.
  • daily-briefing shows "failed": run node -v in Command Prompt to check that Node.js is installed. Also check that the whole key is in the file, right after X-API-Key: with no space.
  • Still stuck? Contact Chuck Konkol (IT).

Claude on the web (claude.ai) can't connect with a key yet. It needs a sign-in flow this API doesn't have.

Example prompts

These work in Claude Code and Claude Desktop once daily-briefing is connected. Start with "Using daily-briefing" or mention "my briefing" so Claude knows to use the connector. Refer to projects by name and Claude looks up the id for you. Dates can be written any way you like ("next Friday", "Nov 15"), and Claude converts them.

Create a project

  • "Using daily-briefing, add a project called 'Upgrade Epicor test server'. Priority High, assigned to Chuck Konkol, start 2026-10-06, end 2026-11-15. Goal: test the new Epicor version before the production upgrade."
  • "Add a project 'Warehouse barcode scanners' to my briefing, status Planning, priority Medium, with these milestones: Requirements by Oct 15, Vendor selection by Nov 1, Pilot by Dec 1."
  • "Add a quick task to my briefing: 'Renew SSL certificate for helpdesk.aquaai.app', due Oct 31, priority Medium."
  • "Add a daily task: 'Check the overnight backup report'."

Update status, dates, and owner

  • "In daily-briefing, set 'OTD metric changes' to Testing."
  • "Move the end date of 'Upgrade Epicor test server' to Dec 1."
  • "Reassign 'Packing List Dashboard' to Dan Burns and set priority to Low."
  • "Mark 'Update Executive Dashboard' as Completed."

Work with milestones

  • "On 'Warehouse barcode scanners', mark the Requirements milestone done with an actual date of today."
  • "Put the Vendor selection milestone on hold. Reason: waiting on a quote from the vendor."
  • "Flag a roadblock on the Pilot milestone: scanner firmware bug, ticket open with the vendor."
  • "Add a milestone 'Go-live' to 'Upgrade Epicor test server' with a base date of Dec 15."

Add notes

  • "Add a note to 'Update Executive Dashboard': deployed to test on 10/5, waiting on Pat's review."
  • "Replace the notes on 'OTD metric changes' with a three-line summary of where it stands."

"Add a note" appends to the existing notes. "Replace the notes" overwrites them, including any formatting from the Dashboard.

Tie it to your code work (Claude Code)

  • "When you finish this change, add a note to my 'Update Executive Dashboard' project saying what changed and the commit hash."
  • "Read PLAN.md and create a project in my briefing for it, with one milestone per phase and the dates from the plan."
  • "Look at the last week of commits in this repo and update the milestones on 'Packing List Dashboard' to match what's done."

Check before you change

  • "What projects in my briefing are in Testing or On-Hold?"
  • "Show me the details and milestones for 'OTD metric changes'."
  • "Which of my projects have a roadblock?"
  • "What's on Mike Hevey's briefing (mhevey)?" Claude can read anyone's briefing but can only change your own.

Good to know

  • Claude asks for your approval before each create or update. Read what it plans to send, then approve.
  • When you change one milestone, Claude reads the full list first and sends it all back, so the others stay put. If something looks off, ask: "Show me the milestones on X."
  • Do these on the Dashboard instead: deleting items, reordering them with Up/Down, attachments, comments, and daily checks. The connector can't do any of them.
  • New items go to the top of their tab, the same as on the Dashboard.

Reference

Endpoints

RequestWhat it does
GET /briefingSummary: owner, department, last update, item counts by section and status.
GET /items/{section}List items in a section. Query options: status=On-Hold, q=words (every word must match), includeCompleted=false, full=1 for every field.
GET /items/{section}/{id}One item with notes, goal, milestones, attachments, comments, and the 10 most recent daily checks.
POST /items/{section}Add an item to the top of the section. name is required.
PATCH /items/{section}/{id}Change an item. Only the fields you send change.
POST /mcpMCP connector endpoint for Claude.

Add ?report=jdoe (any Aqua Network ID) to a GET to read someone else's briefing. Without it, you get your own.

Sections

{section}Dashboard tab
projectsActive Projects
quickTasksQuick Tasks
dailyTasksDaily Tasks. These don't use status, priority, or assignedTo.

Item fields (POST and PATCH)

FieldValue
nameText, up to 200 characters. Required on POST.
statusOne of: Planning, Requirement Gathering, Training, In Progress, Development, Testing, Review, Delayed, Future, On-Hold, Completed, Follow-Up, Maintenance, On Track. New items default to On Track.
priorityHigh, Medium, or Low. Defaults to High.
assignedToOwner's name. Defaults to N/A.
goal, tester, collaboratorsText. Collaborators are team tags, for example "Design Team".
startDate, endDateYYYY-MM-DD, or "" to clear.
notesPlain text; each line becomes a paragraph. Replaces the existing notes, including any formatting.
appendNotesPlain text added to the end of the notes (PATCH only). Use this for log-style updates.
milestonesThe full milestone list (below). It replaces the existing list, so GET the item first and send back every milestone you want to keep.

Text fields can't contain < or >; the API removes them. Last Updated is set for you on every change. Unknown fields are rejected with a list of the allowed ones.

Milestone fields

FieldValue
nameRequired. Milestones without a name are dropped.
baseDateBase complete date, YYYY-MM-DD.
estActDateEstimated or actual complete date, YYYY-MM-DD.
donetrue when complete.
inProgress, onHold, roadblockAt most one can be true.
holdReason, blockReasonWhy it's on hold or blocked. The roadblock reason shows on the Status Report.

Responses

GET /items/{section} returns a short form of each item:

{
  "reportId": "jdoe",
  "section": "projects",
  "count": 1,
  "items": [{
    "id": "item_1791214794883pmnhjmd",
    "name": "Update Executive Dashboard",
    "status": "On Track",
    "priority": "High",
    "assignedTo": "Jane Doe",
    "endDate": "2026-10-31",
    "lastUpdated": "10/5/2026, 8:10:11 AM",
    "milestones": "1/2 complete",
    "nextMilestone": { "name": "Publish", "date": "2026-10-06" }
  }]
}

POST, PATCH, and GET /items/{section}/{id} return {"reportId", "section", "item"}, where item has every field. Notes come back as plain text.

Errors

Errors return an HTTP error status and {"error": "what went wrong"}.

StatusMeaningWhat to do
400Something in the request isn't valid: bad status, date format, section name, or unknown field.Read the error message; it names the field and the allowed values.
401The key is missing, mistyped, or revoked.Check the header is Authorization: Bearer dab_... with the whole key. If it was revoked, create a new one. If the message says That is not an API key and you used %DAB_API_KEY%, open a new Command Prompt (see Step 1).
403You tried to change someone else's briefing, the account is disabled, or the Network ID isn't linked yet.Change only your own briefing. Sign in to the Dashboard once to link your Network ID. For a disabled account, contact IT.
404No item with that id in that section, or no briefing for that Network ID.List the section again to get the current id. Check the section name.
500Server error.Try again. If it keeps happening, contact Chuck Konkol (IT).

Good to know

  • New items go to the top of their tab, like items added on the Dashboard.
  • The Dashboard updates live, so API changes appear right away if it's open.
  • A change made through the API is stored the same way as a Dashboard edit, so it shows on the briefing and the Status Report.
  • Every change is logged with the first few characters of the key, so a misbehaving key can be traced and revoked.
  • Questions or problems: contact Chuck Konkol (IT).
